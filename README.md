# werner-expo

A React Native / Expo practice app, built while working through a workshop that moves React web engineers to React Native. Each concept lives on its own screen, reachable from a drawer menu and an overview screen.

Tested on the iOS simulator and the Android emulator, both running a development build. Web is not tested.

## Tech stack

- Expo SDK 58, React Native 0.88, React 19.3 (React Compiler enabled). SDK 58 was needed for Xcode 27: iOS 27 requires the UIScene life cycle and SDK 57 does not generate it
- Expo Router with typed routes (file-based routing, drawer navigator)
- TypeScript in strict mode
- `@react-native-community/datetimepicker`, `expo-notifications`, `expo-dev-client`, `expo-sqlite`, `expo-camera`, `@shopify/react-native-skia`
- `@faker-js/faker` for sample notes, loaded lazily (about 0.8 MB of the production bundle: 6.4 MB without it, 7.2 MB with it)
- pnpm

## Getting started

### Prerequisites

- Node.js and pnpm
- iOS: Xcode with an iOS simulator
- Android: Android Studio with the SDK, JDK 17 and a virtual device (`ANDROID_HOME` set)

A step-by-step machine setup and a list of problems you may run into are in [docs/SETUP.md](docs/SETUP.md).

### Install and run

```bash
pnpm install
pnpm start:dev     # iOS simulator and Android emulator, through the development builds
pnpm start:go      # Expo Go, only for quick checks on iOS (no own native modules)
```

`expo-dev-client` is installed, so a plain `pnpm start` targets the **development build** by default. The two scripts above set the mode explicitly. You can also press `s` in the Metro terminal to switch.

| Platform | Run with | Notes |
| --- | --- | --- |
| iOS simulator | `pnpm start:dev`, then `i` | Needs the iOS development build (`npx expo run:ios --no-bundler`). CocoaPods is installed by the first run. |
| Android emulator | `pnpm start:dev`, then `a` | See below |

### Android development build

Notifications do not work in Expo Go on Android, so Android uses a development build:

```bash
npx expo run:android --no-bundler   # first build takes roughly 10 minutes
pnpm start:dev                      # then start Metro and press a
```

This generates `android/` from `app.json` and the config plugins, then installs `com.plumotwerner.wernerexpo` on the running emulator. Note that `pnpm android` and `pnpm ios` now run native builds; use `pnpm start:go` or `pnpm start:dev` for day-to-day work.

### Both simulators from one Metro

Both platforms run a development build and load their JavaScript from the same Metro server, so a saved change shows in both.

```bash
pnpm start:dev                                   # one Metro, in one terminal

# Android: connect the development build to Metro (replace the IP if it changed)
adb reverse tcp:5080 tcp:5080                    # only for the API
adb shell am start -a android.intent.action.VIEW \
  -d "exp+werner-expo://expo-development-client/?url=http%3A%2F%2F192.168.50.241%3A8081"

# iOS: press i in the Metro terminal, or open the development build by hand
xcrun simctl openurl booted "exp+werner-expo://expo-development-client/?url=http%3A%2F%2F192.168.50.241%3A8081"
```

Check that both are connected: `curl -s localhost:8081/json/list | grep appId` lists `com.plumotwerner.wernerexpo` twice, once per platform (iOS and Android). Press `r` in the Metro terminal if a screen does not update.

- Run one native build at a time (`run:ios` and `run:android` one after the other). Two builds started in parallel collide, for example while CocoaPods is being installed.
- Your own LAN IP is `ipconfig getifaddr en0`. The Android app loses Metro when it changes.
- Native changes (`app.json`, plugins, native packages) reach a platform only after its native build (`npx expo run:android --no-bundler` or `npx expo run:ios --no-bundler`). `android/` and `ios/` are generated and git-ignored: after a SDK upgrade delete them and run `npx expo prebuild`.

### The API (optional)

A tiny .NET 10 minimal API serves sample notes. It needs the .NET 10 SDK and listens on `http://localhost:5080` only.

```bash
pnpm api          # dotnet run --project api/NotesApi
curl http://localhost:5080/notes
```

Every call returns 50 notes with new GUIDs, so the app never receives the same note twice. In the Notes screen, **Add sample notes** opens a dialog where you choose Faker (100 generated notes) or Server (50 notes from this API).

| Where the app runs | Address it uses |
| --- | --- |
| iOS simulator | `http://localhost:5080` |
| Android emulator | `http://localhost:5080`, after `adb reverse tcp:5080 tcp:5080` (repeat after every emulator restart). The earlier address `http://10.0.2.2:5080` was replaced by this, so both platforms use one URL. |
| Anything else | Set `EXPO_PUBLIC_API_URL` |

#### Images endpoint

`GET /images?page=0&pageSize=50` returns `{ total, page, pageSize, items: [{ id, order, imageUrl, description }] }`, ordered by `order`. A page past the end returns an empty list, an invalid page or size returns 400, and the maximum size is 100.

The 2000 items live in a SQLite file, `api/NotesApi/App_Data/images.db` (git-ignored, rebuilt on start). FluentMigrator creates the table and inserts the items generated by Bogus (MIT) with a fixed seed, so every machine gets the same data. The migrations run at startup and are not repeated. The terminal shows every requested page with the order, id and image URL of each item.

After changing the API code, restart `pnpm api`. In Development `&delayMs=800` delays the answer, which is a test hook for the loading indicator.

A physical phone cannot reach `localhost`. That needs the API to listen on the network and `EXPO_PUBLIC_API_URL` to point at the machine's address. The API uses plain HTTP; a production app would need HTTPS.

## Platform notes

- **Notifications:** `expo-notifications` logs an error when imported in Expo Go on Android. `src/utils/notifications.ts` therefore loads it with a lazy `require` and detects that environment, so the screen shows an explanation instead. Remote push notifications are not implemented.
- **Notification taps:** the scheduled notification carries `data.url`. `useNotificationNavigation` is mounted in the `(exercises)` layout, so the navigators exist when it fires, and calls `router.push` for a running app and for a launch from a tap. A cold start from a tap was verified on the Android development build.
- **Date picker:** iOS renders `DateTimePicker` inline; Android opens a dialog through `DateTimePickerAndroid`.
- **Keyboard:** `KeyboardAvoidingView` uses `padding` on iOS only; Android resizes the window itself.
- **Back button:** the Android hardware back button is intercepted on the details screen. iOS has no equivalent, so the swipe-back gesture applies there.

## Deep links

The app scheme is `wernerexpo`. Every route above can be opened directly:

| Environment | Example |
| --- | --- |
| Development build | `wernerexpo://form` |
| Expo Go | `exp://<your-ip>:8081/--/form` |

Opening `/navigation/details` directly still gives the back button a screen to return to, because `navigation/_layout.tsx` sets `anchor: "index"`.

## Good to know

- `pnpm-workspace.yaml` denies the `unrs-resolver` build script so that installs finish without an error. It is only a helper of the ESLint config.
- `scripts/reset-project.js` comes from the Expo template and would wipe the exercises. Do not run it.
